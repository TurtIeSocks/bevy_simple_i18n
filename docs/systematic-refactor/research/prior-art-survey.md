# Prior-art survey: runtime i18n in Bevy (state of 2026-07)

## 1. bevy_fluent — https://github.com/kgv/bevy_fluent

- **Status: actively maintained, the de-facto leader.** v0.15.0 (2026-06-22) → **Bevy ^0.19**. 46k total downloads, ~1.8k recent. v0.14→bevy 0.18 (2026-03), v0.13→0.17 (2025-10). MIT/Apache-2.0.
- **Architecture** (docs: https://github.com/kgv/bevy_fluent/blob/main/doc/en-US.md):
  - `ResourceAsset` = raw `.ftl` Fluent file (messages/terms/attributes).
  - `BundleAsset` = manifest file `.ftl.ron` (also `.ftl.yml`) — content is literally `( locale: "en-US", resources: ["hello_world.ftl"] )`. One manifest per locale dir.
  - `Locale` ECS **Resource**: `Locale::new(langid!("ru-RU")).with_default(langid!("en-US"))` — requested + default = fallback chain (interpolates intermediate parents, e.g. ru-RU → ru → en-US; example tree has `locales/ru/ru-BY/`).
  - `LocalizationBuilder` = **SystemParam**; `localization_builder.build(&loaded_folder_handle)` → `Localization` (ordered FluentBundle fallback chain). Lookup via `fluent_content::Content`: `localization.content("hello-world")`, args via `"key?arg=value"` request syntax.
  - **Discovery**: either explicit `asset_server.load("locales/en-US/main.ftl.ron")` or `asset_server.load_folder("locales")` + poll `LoadState::Loaded`.
- **wasm**: no wasm-specific code in repo (code search: zero hits for `wasm32`). `load_folder` is unsupported on web (no dir listing) → wasm users must load explicit manifest handle lists. Works, but the "glob/folder" happy path is native-only.
- **Criticisms from upstreaming analysis** (https://github.com/bevyengine/bevy/discussions/11277, Jan–Feb 2024, alice-i-cecile/TimJentzsch et al.): sparse docs; needs extra deps `unic-langid` + `fluent_content` just to start; `BundleAsset` naming collides with Bevy concepts; **language switch requires manually rebuilding `Localization`** (users wanted `Locale::set()`-style reactivity); tight folder coupling; awkward arg passing. Deps of 0.15: `fluent ^0.16`, `fluent-langneg ^0.13`, `intl-memoizer`, `unic-langid ^0.9.4`, `ron ^0.12`, `serde_yaml`.

## 2. Other Bevy i18n crates

- **bevy-intl** 0.3.0 (2026-05-05, Bevy **^0.18**, 1.5k dl) — https://github.com/DelsarteAdam/bevy-intl. JSON per-locale folders (`messages/en/ui.json`), namespaces, CLDR plurals via `intl_pluralrules`, gender axis, gender×plural nesting, exact-count keys (`"0"`,`"1"`) override CLDR categories, reactive `I18nText` component + `LanguageChanged` event, fallback lang, `set_lang_i18n()`/`set_fallback_lang()`. **BUT**: desktop reads `messages/` from raw filesystem (bypasses Bevy asset system entirely), wasm bundles at build time **via build.rs** (`bundle-only` feature for single binary). No hot reload. Closest feature-set competitor but architecturally not asset-driven — exactly the compile-time-embed pattern we're leaving.
- **bevy_easy_localize** 0.6.0 (2024-11-06, **Bevy ^0.14, stale**, 13k dl) — https://github.com/0crispy/bevy_easy_localize. Single CSV as Bevy asset (row=key, column=language), `Localize` resource, component to auto-set `Text`, **hot reload via the asset system works**, auto-detect via `sys-locale ^0.3`. Validates CSV-as-asset+hot-reload; abandoned.
- **bevy-translation-table** 0.1.0 (2024-07-12, single release, dead, 1.3k dl) — CSV/ODS tables, in-code locale switch. Ignore.
- **bevy_mod_localization** (TimJentzsch, mentioned in #5874) — never published to crates.io; WIP abandoned.
- **bevy_yarnspinner** 0.8.0 (2026-03-02, Bevy ^0.18, 18k dl) — dialogue-only but best-in-class localization UX: `Localizations { base_localization, translations }` (BCP 47), **CSV strings files per language keyed by auto-generated line IDs** (`#line:13032079` injected into source in dev via `DevelopmentFileGeneration`), stale rows get `NEEDS UPDATE` prefix instead of overwrite, `DialogueRunner::set_language()` / separate `set_text_language()`+`set_asset_language()` (text in one language, VO in another), per-locale asset folders `dialogue/en-US/13032079.mp3`, missing translation → base-language fallback. Docs: https://docs.yarnspinner.dev/yarn-spinner-for-other-engines/bevy/localisation
- **bevy_gettext / bevy_i18n / bevy_localization**: no such crates on crates.io (name `bevy_i18n` unclaimed as of today). `bevy_simple_text_input` = text-entry widget, not i18n.

## 3. System locale detection

- **sys-locale** 0.3.2 (2024-11-01, 1Password, 25M downloads, 6.8M recent — ecosystem standard) — https://github.com/1Password/sys-locale. `get_locale() -> Option<String>` (+ `get_locales()` iterator since 0.3.0). Platforms: Windows, macOS/iOS/watchOS/tvOS/visionOS, Linux/BSD/UNIX, **Android**, **wasm-in-browser via `js` feature** (navigator.language, needs web-sys/wasm-bindgen). `no_std`+alloc everywhere except Linux/BSD. No Bevy coupling.
- **bevy_device_lang** 0.6.1 (2025-10-03, rustunit, 12k dl) — https://github.com/rustunit/bevy_device_lang. Single fn `get_lang() -> Option<String>`. Impl per platform: iOS/macOS `NSLocale preferredLanguages` (objc2), Android `Locale.getDefault().toLanguageTag()` (jni + ndk-context — works inside Bevy's android-activity context, which is its raison d'être vs sys-locale), wasm `Navigator.language()`, Windows `GetUserDefaultLocaleName()`, Linux `LC_ALL`/`LC_MESSAGES`/`LANG`. **No bevy dependency at all** (deps: jni, ndk-context, objc2, objc2-foundation, web-sys, windows) → version-proof. Pick this for mobile-correct detection; sys-locale is fine if Android is out of scope.

## 4. Fluent vs key-value + `%{var}`; ICU4X status

- **Fluent** (fluent-bundle 0.16.0, 2025-05-22, maintained): asymmetric localization — translators add plurals/genders/case-selectors in FTL without source changes; terms, attributes, number/date formatting built in. Costs for games: FTL syntax learning curve for modders/translators, 4+ extra deps (fluent, fluent-langneg, intl-memoizer, unic-langid), no compile-time key checks, runtime lookup returns `Option` (silent missing keys), overkill for HUD-string games. Fluent's own plural handling wraps `intl_pluralrules` (CLDR).
- **Key-value + `%{var}`**: trivially editable (JSON/YAML/CSV), mod/language-pack friendly, diff-able; weak on plurals/genders unless you add a convention. Middle path proven by bevy-intl: **key-value with optional CLDR-plural/gender sub-keys**, powered by `icu_plurals` — full CLDR correctness (Polish few/many, Arabic 6 forms) without Fluent syntax.
- **MessageFormat 2.0**: spec hit Final Candidate ~Mar 2025 (https://blog.unicode.org/2025/01/messageformat-20-final-candidate-review.html); tech-preview impls are ICU Java/C++/JS only. **ICU4X has NOT shipped MF2** (still out of scope; `icu_experimental` 0.5.0 doesn't include it). Rust MF2 today = `mf2_parser` 0.1.1 (Oct 2024, parser+AST only, Deno tooling) and triesap/mf2-i18n (early, no_std core, Feb 2026). **Not a production path for us in 2026.**
- **ICU4X 2.x — yes, bump for 0.4:**
  - `icu` meta 2.0.0 (2025-05-07) → 2.2.0 (2026-04-01). CLDR 47, Unicode 16, more no_std, owned/borrowed variants, compiled_data default. wasm-clean.
  - **`icu_locid` is formally deprecated** (its 2.0.0 of 2025-10-14 is a tombstone stub) → **`icu_locale_core` 2.2.0** (same `Locale`/`LanguageIdentifier` + `langid!`/`locale!` macros).
  - **`fixed_decimal` 0.5.6 → 0.7.2**: `FixedDecimal` → **`Decimal`** (plus `UnsignedDecimal`); `ryu` feature still exists.
  - **`icu_decimal` 1.5 → 2.2.0**: `FixedDecimalFormatter` → **`DecimalFormatter`**; constructors now take **preference bags** not `&DataLocale` — `DecimalFormatter::try_new(prefs, options)` with `prefs: DecimalFormatterPreferences = (&locale).into()`.
  - Our Cargo.toml today: `icu_locid = "1.5.0"`, `fixed_decimal = "0.5.6"`, `icu_decimal = "1.5.0"` — all three superseded; migration is mechanical renames + preference-bag constructor.

## 5. Community signal (Bevy official)

- No i18n working group, no RFC, nothing on the 0.19 milestone. Two canonical threads:
  - #5874 "Internationalization in Bevy" (2022→2023, https://github.com/bevyengine/bevy/discussions/5874): asks = font fallback for CJK/Arabic, styled spans inside localized strings, CLI tooling for missing-key detection, **runtime text editing so translators iterate live**, crowd-sourcing integration.
  - #11277 "Analysis of bevy_fluent for upstreaming" (2024, https://github.com/bevyengine/bevy/discussions/11277): consensus = **upstream only basic locale infrastructure** (unic-langid-based `Locale` + a `Localization`-ish trait for crate interop); ecosystem crates carry the formats. Pain points named: `Locale::set()`-style switching without manual rebuild, less boilerplate asset loading, args ergonomics.
- Recurring user wants across threads/crates: **hot reload for translator iteration, runtime language packs / mod support (drop a folder in, no recompile), automatic re-render of text entities on locale change, system-locale auto-detect.**

## 6. Non-Rust engine UX reference

- **Godot**: translations are imported **resources** (CSV → `Translation`, or gettext `.po`); `TranslationServer.set_locale()` flips the whole UI — Controls auto-retranslate via `NOTIFICATION_TRANSLATION_CHANGED`; `tr()`/`tr_n()` for plurals; extra `.translation` files loadable at runtime = free language packs.
- **Unity Localization package**: `Locale` assets + String/Asset **Table collections**; `LocalizedString` references auto-update bound UI on locale change; Smart Strings for plural/gender/select; per-locale tables lazy-loaded via Addressables; explicit locale fallback chains; pseudo-localization tool.

## 5 design lessons for bevy_simple_i18n

1. **Locale files must be first-class Bevy `Asset`s loaded via `AssetServer`** (like bevy_easy_localize/bevy_fluent, unlike bevy-intl's raw-FS/build.rs hybrid) — that alone buys hot reload, wasm via HTTP fetch, and runtime language packs for free. Avoid `load_folder`/glob as the *only* path: it's broken on wasm; support an explicit locale list (Resource or plugin config, e.g. `locales = ["en", "ja", ...]` → deterministic paths `locales/{locale}.json`) with folder-scan as native-only sugar.
2. **Locale switching must be reactive, zero-ceremony**: mutate one `Res<I18n>`-style resource (`i18n.set_locale("ja")`) and every `I18nText`/`I18nNumber` entity re-renders automatically (change detection on the resource + asset-event-driven refresh). The #1 complaint about bevy_fluent is manual `Localization` rebuild; Godot/Unity both auto-retranslate.
3. **Keep key-value + `%{var}`, add CLDR plurals as optional sub-keys via `icu_plurals` 2.x** — don't adopt Fluent (dep weight + syntax tax; bevy_fluent already owns that niche) and don't wait for MF2 (no ICU4X impl). bevy-intl's JSON shape (plain string | plural map | gender×plural nesting, exact-count overrides) is a proven middle ground that stays translator/mod-editable.
4. **Bump the ICU stack for 0.4 and ride ICU4X 2.2**: `icu_locid 1.5` → `icu_locale_core 2.2` (icu_locid is deprecated), `fixed_decimal 0.5.6` → `0.7.2` (`FixedDecimal`→`Decimal`), `icu_decimal 1.5` → `2.2` (`FixedDecimalFormatter`→`DecimalFormatter`, preference-bag constructor). Mechanical, wasm-clean, and unlocks `icu_plurals` from the same family.
5. **Fallback chain + system detection are table stakes**: explicit per-locale fallback (ja-JP → ja → default, like bevy_fluent's `Locale::new().with_default()` and Unity's fallback chains), missing-key → fallback → key-echo with a `warn!` (translator-visible, never a panic); auto-detect initial locale via `bevy_device_lang` 0.6 (bevy-independent, Android/iOS-correct) or `sys-locale` + `js` feature, overridable by user save data.
